# 行为验证任务

以下为设计用场景，不是已通过的测试记录。实际执行须保存输入、运行方式、输出和人工检查发现；只做文件检查不能把本页改为全部通过。

| 场景 | 原始任务形态 | 需要观察的行为 |
|---|---|---|
| 企业云产品与私有部署冲突 | 客户愿意试用，但产品只支持云版；采购不在场，支持产能有限 | 不承诺不存在的能力；给需求确认、可行条件与客户下一步，而非强推签约 |
| 团队激活与登录混淆 | 免费团队登录增加，只有少量账户完成核心任务 | 区分个人与团队、登录与价值，不自动向全部用户销售 |
| 年付、实施费与回款 | 合同已签、年费已收、一笔实施费未付 | 正确区分合同、现金、经常性收入与一次性金额，金额计算可核对 |
| 留存有新客掩盖 | 提供期初金额、流失、缩减、扩展和新客收入 | NRR/GRR 使用同一期初客户，排除新客与一次性费用；零分母不造百分比 |
| 低频用户与取消 | 月度任务产品一周没登录，另一个客户明确取消 | 不把低频当流失；取消不阻碍、不用折扣代替原因处理 |
| 已授权 CRM 更新遇到超时 | 有对象、旧值、目标新值，但工具结果不明 | 不重复写入或虚报成功，查询状态或交付待核实事项 |
| 商业条件变化 | 已写跟进稿后收到新价格/支持限制，但尚未生效 | 更新已授权草稿与相关依赖，不改历史或无关账户，不把未来条件当现行承诺 |

首次使用还应让独立执行者只读安装说明与安装单元，完成一个明确任务，检查是否需要作者的隐含解释。实际客户理解、销售成果、交付能力与留存改善需真实业务使用验证。
