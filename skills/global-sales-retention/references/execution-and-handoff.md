# 执行与交接

## 沿用现有工作方式

优先使用用户已有客户资料和记录格式。单次任务可以直接交付草稿或分析；长期协作再保存最少必要状态，不为所有客户新建固定账本。业务资料留在用户指定项目中，和技能文件分开，公开仓库不保存个人联系方式、账户数据、内部路径或客户原始沟通。

记录只保留推进必需的事实、事实发生时间/来源、尚未确认的解释、当前责任人与下一步。客户原话、内部推断和建议不要混写。用户指定的新事实覆盖旧事实时更新已授权范围内的相关草稿和状态；历史记录保留，未经确认的未来价格和日期不能变成现行条件。

## 外部动作如何完成

用户明确要求更新 CRM、发送指定跟进或进行客户操作时，先核对实际工具、账户、对象及授权范围。对象模糊或条件缺失就先完成变更预览并问必要问题；已有充分授权时无需重复确认。

写入前读取当前记录，核对账户/联系人 ID 和当前状态。只修改任务相关字段，保留其他负责人的信息与历史；遇到并发变化先重新核对。发送前检查客户语言、收件人、附件或链接、价格与承诺、停止触达状态；批量操作要有明确范围与数量，不从一封邮件扩展到所有联系人。

完成后核对返回的记录、消息 ID 或可读状态，说明实际发生了什么。对“草稿已创建”“消息已提交”“已送达”“客户已回复”分别报告；没有送达证据不能说已送达，创建 CRM 跟进事项不等于客户已完成动作。

接口超时或响应含糊时，先查询相应对象和最近动作；无法确认是否成功就停止重试并说明待核实，避免重复发送、扣款或修改。明确未执行的失败可在原因修复后按原授权重试，不能扩大条件；不可用工具则交付对象、内容、所需动作和核对方法。

## 五部分之间传什么

市场/战略资料提供目标客户、购买原因和进入条件；内容资料提供可使用的价值表达与证明边界；获客资料提供线索来源、兴趣场景、已交流内容和触达权限。本模块可以直接接收普通文本和文件，不要求其他技能安装。

向交付或客户成功交接购买任务、实际承诺、范围、关键角色、验收与付款状态、风险和下一项客户动作。向实验流程交接观察到的阻碍、来源与时间、可比数据口径、待验证解释和拟变更内容；没有做过实验不能写成已验证结论。

反向反馈应具体：哪些客户在什么任务上出现重复障碍、现有证据支持什么、还缺什么。战略或内容负责人决定是否改定位或资产；不要因一个客户提要求就无授权改掉全部网站、报价和增长计划。
